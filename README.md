# Word4Free

**A free, open-source document editor built for the web.**

Word4Free aims to make document editing accessible to everyone through a modern browser-based experience. The project is designed as an independent alternative to traditional word processors, with a focus on simplicity, accessibility and community-driven development.

🌐 **Website:** [https://word4free.github.io/](https://word4free.github.io/)  
💻 **Source Code:** [GitHub Repository](https://github.com/word4free/word4free.github.io)  
📜 **License:** [MIT License](LICENSE)

## ✨ Features

- 📝 Browser-based document editing.
- 🎨 A modern interface inspired by desktop word processors.
- 📄 DOCX export.
- 📕 PDF export.
- 🌐 Access through GitHub Pages.
- 🆓 Free to use.
- 🤝 Open-source development and community contributions.

*Features may vary depending on the current version.*

## 🚀 Getting Started

### Use Word4Free online

Visit [word4free.github.io](https://word4free.github.io/) to access the application, provided GitHub Pages deployment is enabled.

### Run locally

1. Clone the repository:

   ```bash
   git clone https://github.com/word4free/word4free.github.io.git
   ```

2. Open the downloaded project folder.
3. Open `index.html` in a compatible browser.

Some features may require an Internet connection if external libraries are used.

## 🤝 Contributing

**Word4Free welcomes contributions from everyone!**

You don't need to be an experienced developer to help. Bug reports, feature suggestions, documentation improvements and code contributions are all welcome.

### Ways to contribute

- 🐛 Report bugs and unexpected behaviour.
- 💡 Suggest new features.
- 🎨 Improve the interface and user experience.
- ⚙️ Optimize performance and code quality.
- 📄 Improve DOCX and PDF export compatibility.
- ♿ Help improve accessibility.
- 🧪 Test the application in different browsers.

### Submit a Pull Request

1. Fork the repository.
2. Create a branch for your changes.
3. Implement and test your improvements.
4. Commit your changes with a descriptive message.
5. Push your branch to your fork.
6. Open a Pull Request explaining what you changed and why.

Please keep changes focused, write clear commit messages and test your code before submitting it.

For major changes, consider opening an Issue first to discuss your proposal.
